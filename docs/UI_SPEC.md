# UI動作仕様

## 基本方針

- 見た目はFigma、動作はこのファイルを正とする
- 確定していない動作を、実装都合で固定しない
- JavaScriptが無効でも本文と主要なリンクへ到達できる構造を優先する

## ヘッダー

- Figma注記どおり、ページスクロール時も追従する想定
- ロゴはサイトトップへのリンクとする
- 「エントリーする」はエントリーフォームへのリンクとする
- 追従時にアンカー先や本文を隠さないようにする
- 追従方式とスクロール時の見た目変化は、実装時にFigma注記を再確認する

## 採用LPのリンク

- 募集要項内の「エントリーする」、「エントリーフォームへ進む」と各「エントリーする」はフォームStep 1へ移動する
- フッターの会社概要、募集要項、プライバシーポリシーのリンク先は未確定
- URLは`docs/PROJECT_STATUS.md`で確定後に設定する

## エントリーフォーム

画面順は以下とします。

`Step 1 → Step 2 → Step 3 → Step 4 → 入力内容確認 → 応募完了`

### 共通

- 現在のステップが分かる進捗表示を設ける
- Step 1〜4と入力内容確認は、同一ページ内で表示を切り替える
- 「次へ」「戻る」はFigmaの文言と配置を確認して実装する
- Enterキーだけで意図せず最終送信されないようにする
- 各ステップの入力値を保持したまま前後移動できることを前提とする
- 同一ページ内の前後移動では入力要素を維持し、入力値を保持する

### バリデーション

以下の生年月日・電話番号の空白処理は仕様確定済みで、ブラウザ側・PHP側へコード反映済み。実ブラウザ・実応募データでの結合確認は未実施。

- 最終送信前だけでなく、各ステップから次へ進む時にも対象項目を確認する
- エラー時は最初のエラー項目へ移動できるようにする
- 必須項目が未入力の場合は次のステップへ進めない
- メールアドレスなどHTMLで形式を指定した項目は、ブラウザ標準の形式チェックを使用する
- 最初のエラー項目へフォーカスし、入力欄の近くにブラウザ標準のエラーを表示する
- 「戻る」操作ではバリデーションを行わない
- 文字数などの詳細な受付条件は管理画面側の `docs/SPEC.md` と `docs/DB_SPEC.md` に従う。個別のエラー表示は実装時に照合する
- 生年月日は前後の半角・全角スペースを除いてから「1990年1月1日」「1990/1/1」「1990-01-01」「19900101」の4形式を判定し、各形式の全角数字も許可する。途中のスペース、NBSP・タブ・改行は許可しない。実在する過去の日付だけをDBへ `YYYY-MM-DD` で保存する。形式エラーでは入力欄の近くに4形式が分かるブラウザ標準のエラーを表示し、サーバー側の判定とも揃える
- 電話番号は前後・途中の半角・全角スペース、NBSP、タブを区切りとして許可する。これらを除いた後に数字・許可済みのハイフン類だけか検証し、ハイフン類も除いた数字列が `0` 始まりの10桁または11桁であることを確認する。改行とその他の空白文字は許可しない。30文字上限は除去前の入力値に適用し、超過時も電話番号欄にブラウザ標準のエラーを表示する
- Step 2・3の選択項目は初期回答なしで表示する。必須セレクトは「選択してください」、必須ラジオは未選択から始め、未選択のまま次へ進めない。任意のFP資格も未選択から始め、回答がなければ未入力として扱う

### 入力内容確認

- Step 1〜4の全27項目を、任意項目・職務経歴書を含めて以下の分類順・入力順に表示する。確認画面で項目を抜粋しない
  - Step 1：氏名、フリガナ、生年月日、電話番号、メールアドレス、現在の就業状況、住所
  - Step 2：保険業界での経験年数、金融業界での経験年数、営業経験年数、マネジメント経験の有無、採用・育成・教育経験の有無、労務管理経験の有無、保険募集管理やコンプライアンス関連経験の有無
  - Step 3：生命保険募集人資格、損害保険募集人資格、FP資格、その他保有資格、直近の勤務先、マネジメント人数、経験業務、主な実績、職務経歴書
  - Step 4：志望動機、自己PR、希望条件、質問・連絡事項
- 選択式の項目は選択肢の表示文言を示す。任意項目が未入力の場合は「未入力」、職務経歴書が未選択の場合は「未選択」と表示する
- 職務経歴書を選択した場合はファイル名を表示する。送信前の確認画面では「アップロード済み」と表現しない
- 自由入力欄の改行を保持し、長文も途中で省略せず表示する
- 修正操作で対応するステップへ戻れるようにする
- 確認画面へ戻った時に入力内容を保持する
- 送信ボタンの連打を防ぐ

### 応募完了

- 送信成功後にのみ表示する
- ブラウザ更新時の二重送信を防ぐ
- 「トップページへ戻る」で採用LPへ移動する

## ファイルアップロード

- Step 3で職務経歴書を受け付ける
- 許可形式、上限容量、ファイル名表示、削除・差し替え動作は未確定
- 仕様確定前にダミー動作を本番仕様として固定しない

- 送信APIとエラー時の復旧方法
- 自動返信と担当者通知
