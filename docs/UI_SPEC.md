# UI動作仕様

## 基本方針

- 見た目はFigma、動作はこのファイルを正とする
- 確定していない動作を、実装都合で固定しない
- JavaScriptが無効でも本文と主要なリンクへ到達できる構造を優先する

## ヘッダー

- Figma注記どおり、ページスクロール時も追従する想定
- ロゴはサイトトップへのリンクとする
- 「エントリーする」はエントリーフォームへのリンクとする
- 追従時にアンカー先や本文を隠さないようにする
- 追従方式とスクロール時の見た目変化は、実装時にFigma注記を再確認する

## 採用LPのリンク

- 「募集要項の詳細を見る」は募集要項詳細ページへ移動する
- 「エントリーフォームへ進む」と各「エントリーする」はフォームStep 1へ移動する
- フッターの会社概要、募集要項、プライバシーポリシーのリンク先は未確定
- URLは`docs/PROJECT_STATUS.md`で確定後に設定する

## エントリーフォーム

画面順は以下とします。

`Step 1 → Step 2 → Step 3 → Step 4 → 入力内容確認 → 応募完了`

### 共通

- 現在のステップが分かる進捗表示を設ける
- 「次へ」「戻る」はFigmaの文言と配置を確認して実装する
- Enterキーだけで意図せず最終送信されないようにする
- 各ステップの入力値を保持したまま前後移動できることを前提とする
- 実際の保持方法は、フォーム送信方式と合わせて決定する

### バリデーション

- 最終送信前だけでなく、各ステップから次へ進む時にも対象項目を確認する
- エラー時は最初のエラー項目へ移動できるようにする
- エラーメッセージは入力欄の近くに表示する
- 具体的な必須項目、文字数、形式条件、文言は未確定

### 入力内容確認

- Step 1〜4の入力内容を分類順に表示する
- 修正操作で対応するステップへ戻れるようにする
- 確認画面へ戻った時に入力内容を保持する
- 送信ボタンの連打を防ぐ

### 応募完了

- 送信成功後にのみ表示する
- ブラウザ更新時の二重送信を防ぐ
- 「トップページへ戻る」で採用LPへ移動する

## ファイルアップロード

- Step 3で職務経歴書を受け付ける
- 許可形式、上限容量、ファイル名表示、削除・差し替え動作は未確定
- 仕様確定前にダミー動作を本番仕様として固定しない

## 未確定の動作

- 各ページの正式URL
- ステップ遷移を別ページにするか、同一ページ内で切り替えるか
- 入力途中保存の有無
- 送信APIとエラー時の復旧方法
- 自動返信と担当者通知
- プライバシーポリシー同意の要否
