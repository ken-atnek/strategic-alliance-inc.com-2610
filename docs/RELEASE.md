# 公開・環境仕様

## 現在の方針

- Astroの静的ビルドを基本とする
- ビルド成果物だけを公開サーバーへ配置する
- デモと本番の設定は、ビルド時の環境変数で分ける
- ふもと旅館採用サイトと同じ公開方法を基準にする

公開URL、デモURL、FTP配置先は未確定です。確定前に実在するURLを仮置きしません。

## 想定コマンド

```bash
npm run dev
npm run check
npm run build
```

正式なscriptsはAstro初期セットアップ時に`package.json`で確定します。

## フォーム送信

XBiz上の既存PHP APIで、入力検証、職務経歴書の非公開保存、応募内容のDB登録、担当者へのメール通知を順に行います。DB登録が完了した場合だけメールを送信します。

- 主送信先（To）：`ken.atnek@gmail.com`
- デバッグ通知先（Bcc）：`debug01@a-fact.co.jp`
- 送信先アドレスとメールサービスの認証情報は環境変数で管理し、フロントエンドへ埋め込まない
- DB登録後はメール送信に失敗しても応募完了画面を表示し、担当者通知に失敗した旨を追記する
- 職務経歴書はPDF・DOC・DOCX、上限5MB。拡張子と内容を検証し、Laravelの非公開領域へランダム名で保存したうえでメールにも添付する
- DB登録失敗時はメールを送信しない。ファイル保存後にDB登録が失敗した場合は保存ファイルを取り除く
- 同一送信画面の識別IDとDBの一意制約により、連続クリックや画面を開いたままの再試行による二重登録を防ぐ
- 再試行時に既存応募のメール結果が未確定ならメールは再送せず、応募受付済みと送信結果未確認の警告を表示する
- 電話番号は半角・全角数字、半角・全角スペース、NBSP、タブ、`-`・`－`・`ー`・`ｰ`・`‐`・`‑`・`‒`・`–`・`—`・`―`・`−` を受け付ける。前後・途中の許可したスペース類とタブを除き、ハイフン類も除いて半角数字化した値が `0` から始まる10桁または11桁か検証する。30文字上限は除去前の入力値に適用する。表示用にはスペース類とタブを除いた表記（数字・ハイフン類の入力表記を保持）、検索用には半角数字列を別々に保存する。括弧・英字・改行・その他の空白文字は受け付けない。管理画面で電話番号を検索する際も同じ文字正規化を用いるが、部分検索に10桁・11桁の条件は適用しない。ブラウザ側とPHP側の判定を揃え、実応募データでのローカル結合確認は完了
- 採用担当者への通知メールの生年月日は、検証・正規化済みのDB保存用日付から `1990年1月1日` 形式に変換する。入力表記は使用しない（コード反映済み・実メール未確認）
- 同一オリジン確認、ハニーポット、サーバー側必須チェックを行う
- デモサイトはBasic認証で保護する
- デモビルドではメール送信APIを含め、`debug01@a-fact.co.jp`だけへ送信する
- 本番ビルドでは`public/api/entry.php`を`dist/api/entry.php`へ含める
- デモ・本番ともフォームの送信先は同一オリジンの`/api/entry.php`とする。APIのJSON成功応答を確認できない場合は応募完了画面へ進めない

### 環境変数

| 変数 | 用途 | 初期値 |
| --- | --- | --- |
| `PUBLIC_ENTRY_API_URL` | フロントエンドから呼び出す送信API。未設定時も同一オリジンの`/api/entry.php`を使用 | デモ・本番：`/api/entry.php` |
| `ENTRY_MAIL_TO` | 主送信先 | `ken.atnek@gmail.com` |
| `ENTRY_MAIL_BCC` | デバッグ通知先 | `debug01@a-fact.co.jp` |
| `ENTRY_MAIL_FROM` | 送信元 | `recruit@strategic-alliance-inc.com` |
| `ENTRY_TEST_MAIL_TO` | デモURLからのテスト送信先 | `debug01@a-fact.co.jp` |
PHP側の環境変数が未設定の場合は上記のメールアドレスを使用します。送信にはXBizサーバーのPHPメール機能を使用し、到達性に問題がある場合は認証付きSMTPへ切り替えます。

### DB接続設定

DB接続情報は公開領域や `entry.php` に記載せず、各Laravelアプリ直下の `entry-config.php` から読み込む。ファイルはGit管理・公開対象に含めない。

- ローカル・本番：`laravel-apps/strategic-alliance-control/entry-config.php`
- デモ：`laravel-apps/demo-strategic-alliance-control/entry-config.php`
- 設定項目：`database.host`、`database.port`、`database.name`、`database.username`、`database.password`、`mail.enabled`
- ローカルの `mail.enabled` は `false` とし、デモ・本番で実送信を確認するときだけ `true` にする
- 職務経歴書の保存先は設定ファイルと同じLaravelアプリの `storage/app/private/resumes/`

本番運用前に以下を確定します。

- 担当者通知と自動返信
- スパム対策
- CSRF対策
- 個人情報保護方針と同意
- 公開サーバー上のDB接続・保存先権限

ローカルではPHP 8.3系で構文確認を行う。ローカルDBへの登録、非公開保存、Laravel管理画面からの表示・取得、電話番号の部分検索、同一送信IDの重複防止を結合テストで確認済み。白紙PDF・DOC・DOCXの保存とファイル内容の一致、PDF表示・DOC／DOCXダウンロードを確認済み。5MB+1バイトは受付APIでHTTP 422となり、DB登録なし。画面側の判定関数は5MBちょうどを許可し、1バイト超過を拒否した。実メール送信とサーバー上の保存権限はデモ環境への配置後に確認する。

Laravelの既存検索テストに未確認のハイフン類（`−`、`‐`）、前後・途中の全角スペースのケースを追加済み。対象テストはSQLiteメモリDBで5件・57アサーション成功。受付側の電話番号30／31文字境界、NBSP・タブ、表示用電話番号の保存値はローカル結合テストで確認済み。受付側の自動テスト基盤・テストファイルは今回追加せず、自動テスト不足を継続課題とする。デモ用 `dist` は再ビルド済みで、`dist/api/entry.php` のソース一致・PHP構文、トップ・応募ページの `noindex`、応募ページの生成済みJavaScript参照を確認済み。ローカルではメール送信を無効化し、DB登録成功・通知失敗の経路を確認した。フォームのStep 1〜4から送信した際の完了画面・通知失敗案内も実ブラウザで確認済み。
